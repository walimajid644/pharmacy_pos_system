# Pharmacy POS: audited open questions

Source review: October 28, 2026. Findings below describe code, configuration, tests, and documentation in this checkout. A source path is evidence that a feature is implemented or documented; it is not proof that the signed-in desktop workflow or physical hardware has passed testing.

## 1. Hardware / environment

- **Printer integration:** Invoices and 80 mm receipts are HTML/CSS print views opened with `window.print()` from `src/views/SalesHistoryView.vue`. Return receipts/credit notes use the same browser print dialog in `src/views/SalesReturnsView.vue`. Product labels render an SVG Code 39 barcode using `src/lib/code39.ts` and print a 75 × 35 mm CSS page from `src/views/ProductsView.vue`. `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/src/lib.rs` contain no dedicated printer driver/plugin or ESC/POS command generator. There is no application-level USB, serial, or network printer transport. The chosen printer and its connection are left to Windows/WebView printing. **UNKNOWN — needs manual check:** which printer models and connection types the pharmacy will actually use, and whether the page sizes align on them.
- **Scanner input:** The POS product search is a normal text input. Its `keydown` handler responds to Enter, arrows, and Escape; exact barcode values are matched in the products query. This supports a scanner that types into the focused field and sends Enter, commonly called a keyboard wedge. See `src/views/POSView.vue` (`searchProducts`, `handleBarcodeInput`, and `#pos-product-search`). There is no serial/USB scanner API, device discovery, scanner protocol, or scanner-specific SDK in `src/`, `src-tauri/src/`, `package.json`, or `src-tauri/Cargo.toml`. **UNKNOWN — needs manual check:** the actual scanner's interface, suffix configuration, and barcode compatibility.
- **Hardware verification:** No physical printer or scanner result is recorded. `NEXT_STEPS_CHECKLIST.md` sections 2–4, `README.md`, `RELEASE_NOTES.md`, and the pending rows of `CLEAN_INSTALL_TEST.md` explicitly leave printer/scanner and signed-in desktop checks open. Backend tests in `src-tauri/src/sales.rs` use barcode strings and database fixtures; they do not exercise real devices. **UNKNOWN — needs manual check:** actual receipt, label, credit-note, and scan results on intended hardware.

## 2. Data & compliance

- **Tax/GST:** `app_settings.tax_rate` is a configurable `REAL` field with default `0` in `src-tauri/migrations/001_app_schema.sql`. The Settings screen reads, validates (0–100), and saves it in `src/views/SettingsView.vue`. POS loads that rate from the settings store (`src/views/POSView.vue`), while Rust checkout reads the current `app_settings.tax_rate` and calculates tax in `src-tauri/src/sales.rs`. The UI's statement that Pakistan GST is "typically 17-18%" is explanatory text, not a hardcoded rate. **UNKNOWN — needs manual check:** the legally correct tax treatment and rate for this pharmacy's products and location.
- **Product regulatory fields:** The `products` table has nullable `drap_registration_number` and integer `controlled_substance` (default `0`) in `src-tauri/migrations/001_app_schema.sql`. Both appear in `src/lib/types.ts` and are saved by `src/views/ProductsView.vue`. Their presence is data storage, not evidence of a complete controlled-substance compliance workflow. After the October 28 follow-up, `src/views/SalesHistoryView.vue` and `src/views/SalesReturnsView.vue` read `show_drap` and print the registration number for controlled products when enabled. Physical output remains unverified.
- **Expiry alerts:** Implemented on screen, not merely in the schema. `src/views/HomeView.vue` queries positive-stock batches and renders a near-expiry count and alert table; `src/views/ReportsView.vue` has a near-expiry report; `src/views/POSView.vue` and `src/components/BatchManager.vue` show warnings. After the October 28 follow-up, these screens use the saved `app_settings.near_expiry_days` value (default 60) from `src/views/SettingsView.vue` / `src-tauri/migrations/001_app_schema.sql`. The dashboard query also includes already-expired positive-stock batches. **UNKNOWN — needs manual check:** the pharmacy's desired threshold and how expired stock should appear in alerts.

## 6. Security

- **Password hashing:** New staff passwords and staff password changes use `bcryptjs` with 12 salt rounds in `src/lib/password.ts` and `src/views/UsersView.vue`, aligned with Rust legacy-password upgrades and signed-in password changes (`src-tauri/src/database_api.rs`). Existing cost-10 hashes remain valid and are upgraded to cost 12 after a successful login; failed logins do not modify them.
- **Session timeout / POS auto-lock:** An October 28 follow-up added a five-minute inactivity policy. `src/App.vue` tracks keyboard/pointer activity, sends bounded keep-alives, and returns to login after idleness; `src-tauri/src/database_api.rs` expires inactive backend sessions before protected commands. `src/stores/auth.ts` clears the unsaved cart on logout. The timeout is a chosen default pending staff review, and the signed-in lock/relogin flow still needs desktop verification. **UNKNOWN — needs manual check:** whether five minutes matches the pharmacy's preferred policy.
